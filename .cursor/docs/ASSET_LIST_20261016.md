# 《Ambush Loop》竖切（院子）资产清单

这份清单可以直接用于竖切：P0 是竖切必须的，P1 是可试玩阶段要的，P2 可以延后。大部分资产用灰盒新做或从现有素材复用，没有哪一项必须花钱。

有一点要先说明：CB/#15 线里的 environment_v2（约 83 个文件）、art/v2（约 81 个）、audio_v2（约 45 个 wav）、约 155 个 GLB 和角色动作，我只知道数量和许可情况，没逐个看过文件[[1]](https://app.notion.com/p/2026-10-15-3fab407a692a81858355ff6cd221cbf0?pvs=21)。所以表里的「可复用」都是**候选**，要在 W1 清点后才能确认。另外 audio_v2 现在缺 LICENSE 文件，补回之前不能算可复用。

## 规划够不够开工？

**结论：W1–W2 可以开工，资产不会卡住模拟核心。但下面这几类规划还没写，会分别卡在 W3、W5 和 W6。**

1. **可读性规范还没有，W3 会卡住。** F.3 要求「文字 ≥ 最小字号规范」，但这份规范现在不存在。还缺扇形透明度、灰色阴影色值、单位尺寸和格子的比例、6 个敌人重叠时的显示规则。建议 W1 和字号规范一起出一页「灰盒可读性规范」，不然 W3 门没法客观判定[[2]](https://app.notion.com/p/2026-10-16-41d1a402652d49548f2fc51ee325271b?pvs=21)。
2. **复用素材没核对过，W1 要先补一项清点。** 盘点只给了数量，没有文件级用途，audio_v2 还缺 LICENSE[[1]](https://app.notion.com/p/2026-10-15-3fab407a692a81858355ff6cd221cbf0?pvs=21)。建议在 W1 第 12 项里加一张清点表；没核对过的素材一律按「新做」排期。
3. **复盘卡的主因判定规则没写，W6 会卡住。** 事件日志列了事件类型，但同一局出现多个原因时（比如开早了，同时侧翼又逃了）选哪个当主因、按什么优先级，规划里没有。这直接决定复盘卡文案、时机反例的断言，还有盲测「失败能指出原因」的打分。建议 W2 和 `events.json` 一起出一份 ADR-RECAP-01。
4. **敌人反应规格太粗，W5 会卡住。** 「还击 / 找掩体 / 逃跑」没写触发条件、反应时间、找哪个掩体、往哪逃。这几个参数决定反例成不成立，也决定敌人需要几种状态显示。建议 W2 出一份 ADR-ENEMY-01，和警报计时一样写死秒数。
5. **布阵流程没有线框图，W3 的 UI 会返工。** 选人 → 放置 → 方向 → 武器 → 弹药分配 → 首枪手和条件，步骤顺序、能不能回退、一屏放不放得下，规划里都没有。教学的具体脚本（在不提示高点的前提下教什么）也还没写。建议 W2 末先画一页低保真线框，W3 照着做。

如果需要，我可以把这份清单写成「开发规划」下的一个子页面，也可以先起草可读性规范或 ADR-RECAP-01。

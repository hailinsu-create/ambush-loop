# Ambush Loop 设计规划 v2：短关卡小队伏击

日期：2026-09-28。性质：新的开发设计基线，尚未实现或完成体验验收。

用户确认的方向：参考其指定合集所代表的战术体验，原创制作，短程化、关卡化；核心为“搜集弹药 → 占领高点 → 埋伏 → 歼灭”。本文件响应用户“重新调整游戏的设计规划，包括玩法，视觉等”，替代旧总计划中的产品定位、阶段排序与美术目标。安装、数据安全、真机、签名和发布质量门槛继续有效。

参考合集：https://space.bilibili.com/352319684/lists/772847?type=season 。本次再次访问未成功；没有看完视频，也没有从视频提取场景或素材。下述方案依据用户描述、当前源码与历史画面，不虚构视频分析。

## 1. 做成什么游戏

一句话：**三名队员、一块小战场、有限弹药；用位置和时机完成一次干净的伏击。**

平台保持安卓横屏、中文、离线单机；首发六个短任务，保留当前关卡 ID。准备期可以控制队员移动、搜集和布置，交火期按准备方案自动执行。深度集中在“在哪里、谁拿什么、什么时候打”，不要求手机玩家同时操作三个角色射击。

工作名继续用 Ambush Loop；对外描述使用“小队伏击战术”。“循环”仅作为失败后复盘重试的系统，不再依赖“第几世”的叙事解释。正式中文名在样板体验稳定后独立确定，不借用参考作品名称或标识。

四项设计原则：

1. **资源改变选择**：多拿一份弹药应有用途，也要有绕路或负重取舍。
2. **地形改变战果**：高点和地面交叉火力都要有价值，不能靠伤害加成掩盖地图无聊。
3. **准备换来爆发**：准备有决策、执行有反馈；缩短没有新信息的等待。
4. **失败能够修正**：玩家能说出一个原因，并迅速修改，而不是背一套隐藏标准答案。

范围边界：六关、三人、现有武器与少量工具；不增加联网、局外刷数值、抽卡、开放世界、载具、自由多层建筑、全图迷雾或战斗中实时走位。新的高度规则是明确新增范围，单独开发；不是纯美术修改。

## 3. 单关节奏与状态

以下为设计目标，不是实测或发行承诺。熟悉后的普通关卡目标约 3–6 分钟，首次教学与失败重试单独统计。

| 玩家阶段 | 目标时间参考 | 主要动作 | 应显示的信息 |
| --- | --- | --- | --- |
| 看简报 | 10–20 秒 | 知道歼灭谁、在哪里、何时能开战 | 一句话目标、一处核心地标 |
| 搜集弹药 | 40–80 秒 | 拿取、分配、选补给路线 | 物品类别、余弹、可拾状态 |
| 占位与布置 | 60–120 秒 | 占高点、补盲区、设射界和工具 | 当前队员射界、遮挡、高点弱点 |
| 执行伏击 | 20–45 秒/次 | 观察计划生效、暂停或倍速 | 目标、弹药耗尽、侧翼威胁 |
| 收尾 | 10–30 秒 | 查看战果、必要补给、撤离或下一接触 | 剩余目标、明确主按钮 |

首两关原则上一次主要交火；后续最多两个有不同战术目的的接触段。若第二波仅让玩家原地再打一遍，则删除或压缩，不用波数充当内容量。具体修改波次表属于玩法变更，不悄悄改旧测试期望。

状态映射继续为 SCOUT → ALERT → SWEEP → 撤离 / 再接触；失败进入复盘。面向玩家主按钮改为“发动伏击”，内部仍可沿用 alarm 命令。按钮说明要写清“开始后自动执行，无法移动”，避免把它理解为按一下同时全员立即开火。

敌人进入战区的时间、路线和入伏条件由关卡作者定义，保证可复盘。首版不加入随机命中、随机刷出点或随机掉落来制造失败。

## 4. 玩法系统

### 4.1 小队：身份清楚，负担适中

| 角色定位 | 主要价值 | 明确弱点 | 第一关职责 |
| --- | --- | --- | --- |
| 侦察/精准火力 | 观察路线、远距窄射界、绕背辅助 | 弹药少，不适合近处多目标 | 高点监视主道 |
| 支援火力 | 压住主通道、处理密集目标 | 耗弹快，侧翼覆盖弱 | 地面交叉火力 |
| 步枪/机动火力 | 补盲区、封出口、携带工具 | 单独难应对密集目标 | 保护高点入口与漏网线 |

不先新增第四角色。初期保留现有角色 ID；展示名、造型和背景独立设计。角色优势通过射界、移动、携行和武器适性表达，不堆主动技能按钮。

### 4.2 弹药与装备：从背包管理转向火力决策

- 保留当前 6 格背包与 10 枪数据兼容；首两关只展示步枪、支援武器、精准武器三类核心选择，其他型号后续引入。
- HUD 默认显示“武器类别 + 剩余弹药”，型号、详细射速等放检查面板；不把内部类别 ID 显示给玩家。
- 第一关提供能完成任务的基础补给，另设一处可选补给。获取可选资源能支持替代战术，不能成为未提示的强制步骤。
- 弹药归属、交换和丢弃沿用明确的背包规则；新增“转交给指定队员”若替换当前最近队友逻辑，单独验证距离、满包、重复点击，不做隐式远程转移。
- 搜索目标分“未搜 / 正在搜 / 已搜”；靠近后出现唯一上下文操作，完成后立即收起。背包满时告知哪类空间不足，掉落留地面。
- 跨波保留当前资源；失败重试重置本次资源、敌人和掉落，只保留情报与方案。不开永久弹药成长。

### 4.3 高点：真实规则，限制复杂度

选用“单一可行走平面 + 两档高度”的实现方向。地面高度 0，高台高度 1；高台有明确坡道/入口，不能点击屋顶瞬移。暂不支持同一平面坐标上下叠站两个人，也不开放自由攀爬。

玩法收益来自**越过低矮遮挡的视线**，首版不同时叠加额外伤害、命中、射程三种奖励。完整墙体仍挡线。高点暴露的入口、近处盲区和窄射界由地图/武器共同形成，不能全图无死角。

需要的规则提案：地形 height_tier、遮挡等级、占位入口、射线高度插值和掩体保护来源。字段名与数据结构由实施切片决定；不先在所有关卡批量填假数据。

必要反例：

- 同一对单位在地面被矮墙挡住，登高后通线；中间完整建筑仍挡住。
- 从目标方向反向检查几何可见性一致；射程/朝向不同导致不能开火要给不同原因，不能混成“高点免伤”。
- 掩体减伤来自实际被保护的方向与遮挡，不能让高点标记绕过所有掩体。
- 没有合法入口时不能上台；敌人按作者路线走到高台入口时能威胁驻守者。
- 预览、模拟、伤害事件、回放使用同一结算依据；不能黄扇形说能打，结算说打不到。

高度涉及旧契约改变，以独立 ADR 和变更集实施，重建受影响的参考结果，保留旧版本证据；不混在纯视觉提交里。

### 4.4 埋伏：两种开火条件足够

首版保留“见敌即打 / 入伏再打”。玩家准备时决定每人的条件，射界和入伏区可以预览。工具聚焦地雷/绊索与预设手雷点，第一关只教射界和时机，不同时教授全部工具。

用户点击“发动伏击”后锁定位置、朝向、开火条件、装备与工具。自动开火和自动手雷遵守准备方案；暂停、倍速、镜头、复盘只能改变观看。实现前审计当前 ALERT 是否仍允许换枪，若与冻结承诺冲突则修正并补回归。

不做半套战中移动或临时点杀，以免用户以为自己能救场，实际规则却不允许。若盲测证明冻结交火缺乏参与感，先压缩执行时长、改善可读性与反馈；实时微操另作产品决策，不悄悄加入。

### 4.5 侦察、歼灭与失败

首发重点是观察、搜集、部署和伏击。已有巡逻/视锥用于辅助观察和绕背，不把当前“被发现仅提示”包装成完整潜入危险系统。M1 要删除或改写会误导玩家认为已经强制开战的提示；新增发现后强制警报或战斗惩罚不在本轮默认范围。

基础胜利：本次规定目标歼灭后确认撤离；失败：目标越过清楚标出的有效逃逸线或小队全灭。前置 UI 要提前标线、说明失败条件。首版不改为“漏一个扣星但继续”，避免与现有硬规则冲突。

结算优先显示“完成/失败、一个真实关键事件、下一步操作”。例如：“东侧目标通过时，机枪手正在朝向主道”，建议另列“下次可尝试让步枪手覆盖东侧”。不将未经验证的原因写成事实。

重试回准备期，显示上一方案的幽灵标记和失败位置；不自动赠送上一局装备。缩短基础补给路径，教学不重复。高级回放默认收起，玩家需要时再展开。

### 4.6 战役与成长

六关顺序解锁，重玩已解锁关卡不丢进度。通关记录、可选挑战和档案提供重玩目标，首版不做永久属性升级。可选挑战以“没有队员阵亡 / 使用替代火力点 / 控制补给消耗”等实际事件为基础，等核心平衡稳定后再配置，不要求所有挑战同时完成。

显示副标题是设计提案，内部 ID 保持兼容；下面是关卡职责，不是逐关已完成说明。

| 关卡 | 核心问题 | 高点与弱点 | 资源/工具重点 | 视觉地标 |
| --- | --- | --- | --- | --- |
| 院子 yard · 断路伏击 | 高点与地面怎样交叉覆盖 | 装卸平台看主道，侧巷需地面队员守 | 三类基础枪，一处可选弹药 | 仓库门、短坡道、孤灯 |

| 泵站 pump · 分流 | 改门后谁去补另一条路 | 检修台跨矮栏观察，管道挡线 | 路线选择、有限工具 | 水池、管线、泵体 |
| 信号楼 railcut · 迟到的侧翼 | 第一批打完为什么不能放松 | 楼外平台覆盖远线，另一侧有延迟入口 | 预留弹药、分工 | 桅杆、拉线、两条错开的通道 |
| 油库 depot · 三面压力 | 高点和多个入口如何取舍 | 罐区之间的观察位，油罐遮挡另一侧 | 工具替代一名守军 | 圆罐、检修梯、橙色工业灯 |
| 电台 radio · 最后一次伏击 | 综合分配与延迟目标 | 台基观察位只能优先照顾一侧 | 波间有限补给、综合方案 | 天线阵列、回波信号灯 |

每关一个新战术问题，最多复用两个旧问题。先有可验证的两种有效方案，再做美术细化；不把所有解都压到同一高台。每关至少记录一个失败方案及其可解释原因。

## 6. 院子样板：先做这一关

战区控制在一屏主要内容加少量平移。入口在安全边缘；基础补给在通往阵地的路径上；装卸高台位于主道侧方；另一端有地面沙袋位；侧巷连接逃逸线。

方案 A：精准火力上高台，支援守地面主道，步枪封侧巷。方案 B：支援使用高台形成另一条主射界，精准火力看出口，步枪护台阶。两案是否成立必须用资源预算与运行结果证明，当前不假定通关。

第一次教学分四个动作，不做三页规则墙：拿一份补给 → 占一个位置 → 调整射界 → 发动伏击。每一步只提示当前动作，完成即消失，帮助入口可重看。首次不强迫玩家搜尸、递枪、匍匐、看完整复盘后才继续。

样板退出：5 位未参与开发的试玩者中至少 4 位能独立发起有效伏击、说出高点的优势和弱点；出现失败后能改一项相关设置。记录求助者与失败者，不只记录成功样本。

## 7. 视觉方向：有体积感、可读的微缩战场

### 7.1 风格与镜头

采用**半写实、风格化的 2.5D 斜俯视军事微缩场景**。场景有厚度、接地阴影、材质差异和清楚的建筑侧面；不追求照片级纹理。镜头固定朝向，默认不旋转，避免手机上失去方向。

技术优先级：沿用 Godot 2D 世界与逻辑坐标，用统一三分之四视角的道具/角色绘制或烘焙资源表现体积；不为了美术直接重写成完整 3D。先证明一个高台、两种墙、三名角色、一个补给箱在实际游戏尺度下可读，再扩资产。

所有视觉高度偏移必须映射回同一可交互锚点；碰撞/选中/路径仍基于真实地面位置。设计草图不决定投影算法，投影转换如需调整，另开输入和坐标验证切片。

### 7.2 颜色与层级

固定“暮色工业场所”基调，六关可从黄昏走向夜间，不再靠全屏压暗制造气氛。下面色值为起始色板，需真机对比后调整：

| 层 | 起始颜色 | 用法 |
| --- | --- | --- |
| 地面与背景 | 冷灰绿 #35433F、土灰 #686154 | 低对比、大形体；弱化重复格纹 |
| 结构与高台 | 水泥灰 #8D9485、旧木 #8E7356 | 顶面较亮，侧面较暗，台阶边缘明确 |
| 玩家与选中 | 军绿 #72836A；选中青白 #A8D6CA | 身体轮廓加角色形状，选中才有底环 |
| 敌人与威胁 | 深灰 #454C51；危险朱红 #D77461 | 制服不满身发红；以菱形/方向/文字补足辨识 |
| 可交互补给 | 暖黄 #D4B774 | 仅交互边缘与短提示，避免全场金色 |
| 界面文字 | 米白 #EEEBDD、辅文 #BFC8BF | 面板底色独立于地面，重要字不压在杂物上 |

渲染优先级：单位/目标与立即危险 > 当前操作对象 > 建筑/掩体 > 装饰。低光区也要看清可走地面与角色方向；选中轮廓不被雨、烟、灯光吞没。

信息叠层规则：默认只显示选中队员的射界；整体覆盖通过一个“战术视图”开关临时查看。高点可射区域实线/淡填充，遮挡与不可射区域用断线和原因，不堆满三层半透明圆锥。地面不常驻武器型号、全部路点时间和长段教学。

### 7.3 角色、敌人与环境

- 三名队员靠体型/持枪姿势/背负装备区别：侦察轻装长枪、支援低姿重装、步枪手中等轮廓。先测黑色剪影能分辨，再加服装细节。
- 敌人先做普通巡逻、快速侧翼、重火威胁三种职责，复用骨架而保留轮廓差别。不要通过多刷相同敌人替代战术变化。
- 地图用“大块结构 + 少量中型地标 + 极少小道具”组织。美术道具必须标记装饰/挡路/挡弹，避免看上去能躲、实际不挡线。
- 前景墙、屋檐遮住玩家时淡化；淡化仅改变显示，不能改变真实遮挡。无头顶整片屋顶遮住可操作角色。
- 首批资产：三名队员与方向帧、两类敌人、箱/弹药/沙袋/矮墙/整墙/高台坡道/灯具。各物体统一光源方向、地面锚点、比例和接地影。

### 7.4 动画与打击感

优先补全待机、走、蹲、拿取、部署、瞄准、射击、命中、倒地九个可读状态；不靠连续晃动代替动画。首版角色方向资源数量由实测成本决定，至少确保射击方向和射界一致。

重要事件反馈链：开匣进度 → 手部动作/箱盖 → 拾取声 → 弹药数字更新；发射 → 短枪口光 → 命中材质/身体反应 → 目标状态。动画跟随结算，不阻塞结算。倍速、暂停、重试后不能残留旧特效。

开火声和短促闪光创造爆发感，画面震动默认轻且可关。提供减弱闪烁/动态选项；不持续全屏红闪、不靠频闪提示每一枪。预设手雷必须给清楚的范围和友军风险。

## 8. 手机 UI 与操作重整

目标布局：地图占主要区域，顶部细任务条，底部一排三人简卡，右侧当前队员的少量动作，右下唯一主操作。完整背包、档案、日志、详细时间轴都通过二级面板打开。

| 操作 | 手机设计 | 边界 |
| --- | --- | --- |
| 选人 | 点底部卡或单位 | 卡优先捕获，不穿透到地图 |
| 移动 | 点空地预览路径/目标标记，再按状态执行 | 点补给、掩体走上下文路径，失败说明原因 |
| 设置射界 | 选中已占位队员后拖动独立方向手柄；提供左右微调按钮 | 与拖镜头区分，取消不提交旧手势 |
| 拾取/占位 | 靠近对象显示单一上下文按钮 | 多对象重叠时弹小选择条，不随机抢目标 |
| 工具 | 打开工具后点合法地点预览，再确认 | 取消不耗资源；不能放到界面或不可走区域 |
| 查看战场 | 双指平移/缩放，另给概览按钮 | 布置手柄正在拖动时不触发镜头手势 |
| 发动/撤离 | 右下主按钮随阶段改名 | 发动前预览说明自动执行，已开始后不再接受布置 |
| 交火中 | 暂停、倍速、观察；复盘在结果后展开 | 工具区明确收起/禁用，不能误以为可微操 |

尺寸先按逻辑界面 48dp 级触控区域设计，再按 Android 实际缩放与安全区换算；不能把 Godot 的 48px 直接宣称为 48dp。主要按钮与相邻输入间隔至少以实测拇指不误触为准，宽高比、刘海和系统手势区都要验证。

首屏原则：一条目标、一条当前动作提示、三个队员状态、一个主按钮。弹药和生命状态用图标/数字/形状共同表达；色盲与静音模式仍能判断。

## 9. 声音、氛围与叙事

声音分环境底、交互、战斗、结果四层。环境声低而稳定，准备阶段可听见风/电流/设备；发动后短暂收低底音，让第一次齐射有对比。步枪、支援火力和精准火力要在节奏、尾音上能区分。

优先做拾取、空弹、岗哨察觉、开战、侧翼来敌、目标越线、成功撤离的稳定声音语言。重要威胁同时有视觉提示；不要求靠耳机左右声道才能过关。不急于加入长对白或主题曲。

叙事采用原创架空工业战区与小队行动简报，保留时代感但独立设计阵营符号、人物、地点、任务文本。每关“为何行动—当前目标—成功后果”各一句以内；通关后的档案作为可选阅读。

## 12. 验收与证据

四类证据分开：源码/自动测试证明规则；同版本截图证明可读性；手机操作证明触控；陌生人试玩证明能理解。历史截图仅作对照。本次只改设计文档，未运行游戏或测试，未生成真实新游戏帧。

- 规则：高点、矮墙、整墙、朝向、入伏、资源转移、工具取消、冻结、波间/跨失败边界，以及 1×/2× 结果一致。
- 读图：在默认手机缩放下辨认三人、敌我、补给、高点入口、射界与出口；三人全选覆盖不能让字和地形糊成一片。
- 交互：拖射界不移动队员，UI 不穿透，遮挡可见对象能正确选中，任何面板都有退出方式。
- 节奏：分别测准备、无决策移动、交火等待、重试；总时长达标但过程枯燥仍不通过。
- 真机：沿用旧计划的数据安全、安装升级、后台/返回、30 分钟稳定运行与目标机性能要求；指标未经测量不得写通过。
- 原创：人物/地图/任务/界面/美术/音效独立制作；第三方资产来源和许可可追溯。不把“换名/缩关/换皮”当作原创证明；发行前单独审查，不承诺法律零风险。

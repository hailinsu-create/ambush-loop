# 协作者 3D 基座迁移与后续开发规划

日期：2026-10-07。状态：用户已确认“以协作者版本为基座”的方向；CB0 本地隔离测试已通过，渲染目检/云端构建仍待；CB1 已开始并完成首个 UI 子切片，后续规则迁移仍按门执行。本文记录规划与实测，不合并 PR #15、不替换已安装游戏。

## 1. 结论与替代关系

采用协作者完整的六关 3D 场景、角色动作、岗哨、战斗/死亡表现、镜头及回放框架，作为后续产品实现基座；把本地成熟的玩法规则与触屏交互逐项移植进去。不是继续在本地简化院子上零散贴模型，也不是把两套 main/presenter 全量硬合并。

保留“搜集弹药 → 占领有利位置 → 埋伏 → 歼灭”的产品方向，以及 `SCOUT → ALERT → SWEEP` 和战斗冻结计划契约。高点是几何/视线优势，不是必走唯一解，也不靠额外伤害倍率伪造价值。

本规划替代旧路线中“本地院子 I0/V1 呈现器作为后续 3D 主体”的技术选择；不撤销已有工程、数据安全、授权和发行门槛，不宣称 M2/M2.5、手机性能、真人体验或 M3 入口已通过。旧 V0–V5 画面目标可重新映射，不能再平行开发第二套 3D 主体。

本文档分支从 main 建立以便单独评审。将来的产品集成分支应以协作者固定提交为源基线；若交付流程要求从 main 建分支，则先在隔离集成分支纳入该固定快照及历史，再逐片接入本地规则。不直接推 main，不改写协作者 PR。

### 已确认的集成缺口

- 本地 `art/environment_v2/M2_I0_SOURCE.md` 记录仅取过旧协作者 `eb50a73` 的四个模型及图集，不是完整合并 PR #15。V1 的地面/主体建筑又主要使用程序几何，角色也不是协作者完整骨骼角色。
- 本地 `c2_director.begin_scout` 本来就生成岗哨；但院子呈现器只同步 `host.enemies`，漏了 `c2.sentries`。因此“报警前看不见敌人”包含呈现接线问题，不能说本地没有岗哨玩法。
- 协作者的 `view_state` / `visual_snapshot` / `presenter_3d` 纳入 ops、enemies、sentries、corpses 等；具有 `actor_visual`、`corpse_visual` 和射击/工具表现池。优先保留这个完整链路。
- 协作者世界映射、角色同步及 `world_picker_3d` 的落点目前以地面为主；本地高度玩法不能只复制高台模型，必须把高度接进快照、显示、拾取和特效锚点。
- 用户反馈的长期卡顿、挡视线、杂线属于真实待解决问题。协作者已有的软件渲染/专项证据不等于同一手机长时间表现优于本地。

## 4. 已发现的冲突及处理决策

以下是源码/规则层面的已发现冲突，不是伪造的 git merge 冲突报告；执行时逐片生成真实补丁和差异审查。

| 冲突 / 风险 | 处理建议 | 必验反例 |
| --- | --- | --- |
| **高：高度与平面显示/拾取不一致。** 本地 height_tier/ramp/LOS 与协作者 y=0 拾取不能直接并存。 | 在协作者快照增加带版本的高度数据；角色、枪口、轨迹、尸体、选择圈、遮挡与拾取同一映射。视线仍以权威规则为准，不切换为偶然物理射线结果。 | 高台站位和点击落点一致；坡道可上、悬边不可跨；低掩体/全高墙分开；回放复现同样高度。 |
| **高：两套触屏/相机入口抢手势。** | 保留协作者 command_router/camera_input 为唯一路由，接本地 intent/confirmation；选择、相机、世界指令和 UI 明确所有权。 | 双指缩放不派发移动；拖镜头不点兵；取消、抬指落 UI、失焦后无迟发指令。 |
| **高：D1 快照不含完整潜行世界。** 现有 capture 主要 crew/stashes；重建 SCOUT 会再生岗哨。 | 扩充契约后才启用：岗哨存活/位置/朝向/怀疑、尸体和携带/拾取、环境交互、奖励消费标志；瞬态 FX 清理。保存点、恢复入口及可恢复阶段明示。 | 击倒/搬运/搜尸后重试不会复制战利品、复活错位敌人或重复发安静院子奖励；失败恢复不改玩家正式存档。 |
| **中高：刀具开局 vs 角色枪+应急弹。** 协作者院子搜枪节奏，本地为 kar98k=1、mg42=3、scout=1 起始弹。 | 推荐院子采用本地“有枪但弹不足”，保留刀/潜行及后续关卡搜枪；不是两边物资简单叠加。院子当前参考箱为 6/47/5（合计 7/50/6），仅作待复验初值。 | 拾枪、切枪、转交和死亡掉落不生成弹药；仍需搜集但不强制唯一箱子路线。 |
| **中高：院子两波 vs 本地一场三目标含侧翼。** | 首关推荐一场清晰接敌；延迟侧翼形成同时威胁，不能只把波数标签改成 1。其余五关先保留协作者内容，不统一砍波。 | 更新六关波次/敌人统计与胜利推进测试，不能沿用旧 13 波总数当新验收；主路/侧翼的出现时机确实重叠。 |
| **中高：旧关卡坐标、模型外观与战术碰撞冲突。** | 以协作者美术尺度为可见外壳，重校本地高地/物资/侧翼路线。每个建筑和掩体可视边界与逻辑 footprint 对齐。 | 不穿墙、不被空气墙挡住；旋转镜头能看见目标；两种部署不依赖一个像素或固定鼠标坐标。 |
| **中高：本地战报/重试与协作者可视回放格式不同。** | 协作者记录器为唯一回放权威；扩展高度/弹药/许可事件 schema，历史原因定位使用当时快照。旧格式要兼容读取或明确不可兼容，不编造缺失字段。 | 复盘不改变实战状态；首次击杀/侧翼漏防位置正确；重试新 attempt 与旧录像分离；旧录像无高度时按声明版本展示。 |
| **中：手机 UI 与桌面密集信息冲突。** 协作者截图也有大量侧栏，不直接照搬手机。 | 战场优先；非选中单位不常显射界；主状态条+折叠队员条+近触点可避让确认。详情点开，打开时阻断世界输入且可一键关闭。 | 横屏小屏/折叠内外屏、左右边缘、系统安全区不遮确认与目标；真实物理触控面积验收，不以截图像素代替 dp。 |
| **中：旧存档、构建身份、导出配置。** | 永久进度、局内重试和只读回放分开版本化；守住 Android package/签名和递增 versionCode，Web 持久化单独测。 | 原位升级不清档；不兼容快照给说明；不存在“测试 APK 其实旧包”；测试/截图/敏感文件不被打包。 |
| **高：画面改善可能加重长局卡顿。** | 同机同场景先测基线；限制常驻 HUD 重建、演员/尸体/FX 实例和材质数量；固定质量档对照，最后才做自动降级。 | 30 分钟实战循环而非静置；后段帧时间、内存、节点/实例数、热状态有记录；不能只报平均 FPS。 |

无需推倒原玩法：部署冻结、岗哨潜行、工具与枪械分工可以共存。暂不加入战斗中自由微操、FOW、联网、第七关或高层建筑系统；这些会改变范围和验收成本。

## 5. 执行顺序（迁移切片 CB0–CB6，不是新增产品里程碑）

### CB0 — 固定协作者原版并重现完整闭环

- 创建隔离产品集成分支，固定 PR #15 快照，记录资源清单/来源/许可、实际启动入口、渲染器和构建身份；旧本地分支仅作能力供体。
- 不先移植规则，先运行其真实入口：开局→SCOUT 岗哨→报警→射击→死亡→结算→回放；六关资源检查，无遗漏材质/动画。
- 先完成六关隔离冒烟、资源/角色/回放/3D 输入与画质合同门。目标设备短基线不在 CB0 冒充完成；按工作区规则留到全部云端/资源门完成后的设备阶段，当前仍待真机。
- 出口：可运行的协作者完整基线、六关与资源测试证据、兼容性风险；用户应首先看到完整人物和战斗，不是新一轮占位模型。设备长局与陌生人门仍留后续，不由云端测试代签。

### CB1 — 手机可用：清爽 UI 与输入所有权

- 保留协作者镜头和指令框架，接入点选/预览/确认/取消；相机拖拽、双指和世界操作不冲突。
- 默认只显示选中单位相关射界、当前路径和必要危险提示；颜色/图例对应明确含义，调试网格/辅助射线默认关闭。
- 常驻信息压缩，战术详情折叠；确认靠近操作目标且避开手指、边界与系统安全区，取消位置稳定。
- 出口：鼠标/键盘不退化；触控专项与布局矩阵通过；至少一段真实手机连贯操作视频待人工核验。

### CB2 — 高点与完整 3D 战术表达

- 先移植高度/坡道/LOS 权威数据，后扩展快照、模型锚点、选择拾取、切顶/遮挡、回放；覆盖岗哨、尸体、道具，而非只覆盖我方人物。
- 接入 `yard_tactical_display_data` 的范围、遮挡、弹药、许可、冷却解释，但重做轻量表现，不复制大信息卡与全场线。
- 出口：同一状态下规则判定、射界显示、实际伤害一致；高地/地面/墙/坡道正反例及相机旋转全覆盖。

### CB3 — 院子战术样板：弹药+两种部署+一次接敌

- 明示修改首关起始装备/补给和波次契约；保留可见岗哨与潜行，不退回报警前空地图。
- 第一解：高地/交叉火力；第二解：地面掩体/正确工具和朝向。保留延迟侧翼，但重新校准协作者地图上的路线、时序和物资位置。
- 用现有 B1/B2 测试的意图建立新地图用例；加入邻近站位/小角度扰动、漏侧翼、缺弹、错误工具的因果反例。旧坐标胜利记录不当新证据。
- 出口：两解真实可赢、有合理操作容差；失败能归因而非隐藏规则；资源守恒且不要求死记唯一部署。

### CB4 — 安全重试、战报与四步教学

- 先补齐世界检查点，再接快速重试；与持久进度分离，定义不兼容旧快照处置。回放沿用协作者系统，记录高度/许可等新增字段。
- 教学短提示穿插实际操作：收集、站位、瞄向、开战；帮助面板按需，不覆盖战斗。失败提示绑定真实历史事件。
- 手动开火许可放在高级可选项，默认自动；不阻塞首局或核心重试交付。
- 出口：反复搜尸/取箱/击倒/重试无物资复制和状态污染；存档隔离、教学关闭/重入、历史定位有反例覆盖。

### CB5 — 手机长局与整体收口，决定 M3 入口

- 在同一冻结源码上跑受影响专项和完整六关隔离回归；wrapper/engine 退出 0、完成标记、每关结果、runtime_errors=0、PLAYER_DATA_UNCHANGED=1 全部核对。日志缺失不算通过。
- 同设备/渲染器/分辨率/质量档/充电条件记录冷启动与 30 分钟连续玩法；采集前后段 p50/p95/p99 帧时间、>100ms 卡顿、内存、实例计数、温度/降频。最低目标稳定 30FPS，60FPS 为可选档；量化阈值须在跑测前锁定并保留旧红灯，不能测后放宽。
- 人工确认预警前敌人、开枪、命中、死亡、尸体均可辨；UI 不遮关键目标；陌生玩家不用讲解可完成院子。数据缺失/手机离线时只暂缓对应门，不冒充通过。
- 出口：已验证的完整 3D 院子+可用六关框架。候选测试包可默认 3D；发行默认切换必须等相应门通过，不通过就保留旧发行与可回退包。

### CB6 — 进入 M3 后扩充六关玩法，而非重做六关美术

| 关卡 | 在已有协作者环境中强化的玩法 |
| --- | --- |
| 院子 yard | 资源与双解法教学、一次主接敌 |
| 仓库 warehouse | 狭道/交叉火力、掩体与火力持续性 |
| 泵房 pump | 门路选择、工具与可见岗哨路线 |
| 铁路切口 railcut | 延迟侧翼、远近火力分工 |
| 仓储区 depot | 多入口与弹药分配压力 |
| 电台 radio | 搜集、潜行、高地/地面选择、侧翼的综合考验 |

每关独立平衡切片，先设计可读威胁再确定波次，不用堆敌人拖长时长。之后进入 M4 外部试玩/性能覆盖/存档与升级测试，M5 才做正式发行包、许可清单和发布回退；不把这次基座调整当作全部阶段重来。

# M2 触屏操作重做提案：先看清，再执行

日期：2026-10-03。状态：**待用户采纳的设计提案，未实施、未做真机 A/B 验收**。

需求来源：用户在继续 M2-B2 前反馈操作问题大、容易误触，要求参考其他游戏提出更好的触屏方案。本轮仅分析与规划，不将询问方案视为授权改写操作代码。

## 1. 基线与判断

审阅源码：`codex/m2-b1-explicit-supplies`，提交 `42ba583e2ce88203543678280b905acb2cda63dd`，源码 Draft PR #25。此前资源切片状态见 [M2-B1 执行记录](AMBUSH_M2_B1_SUPPLY_EXECUTION_20261003.md)。

主要问题不是玩家手不准，而是同一手势承担多种命令，且看地图与下命令之间缺少稳定边界。M2-A 简化了信息显示，并没有完成输入契约重做。

源码证据（静态检查，不等同于本轮真机复现）：

- `ambush_loop/scripts/main.gd::_handle_touch_gestures`：单指拖动在选中人物附近优先改朝向，其他位置累计移动达到阈值后平移镜头；同样的拖动会因起点改变含义。
- 同函数的朝向拖动分支设置 `_touch_dragged`，但没有清除 `_pending_setup_touch`；松手分支先清除 `_facing_touch`，随后仍可能进入 tap/sprint 的 `_handle_setup_click`。因此存在改朝向后又发移动/部署命令的代码路径风险，尚未录制真实设备复现。
- `TOUCH_SPRINT_MS=280`、头像 `LONG_MS=350`、`COVER_LONGPRESS_MS=400`：不同位置上的长按承担冲刺、头像附加动作、掩体预览等不同职责，不能靠记住时长解决。
- 人物附近判断使用 44 世界单位，镜头拖动阈值使用 22 屏幕坐标单位；缩放后两者的体感关系会变化。
- `c2/context_prompt.gd` 的上下文按钮位置/命令随对象刷新，执行时读取按钮当前元数据。应补充按下到抬起期间目标和动作不变的契约，避免动态 UI 抢走原意；本轮没有证明实机已发生该类误触。

## 2. 参考什么，不照搬什么

1. **Company of Heroes 手机版**：官方提供右下命令面板和长按命令轮盘；轮盘允许拖回中心取消。借鉴稳定的动作入口与明确取消，不照搬多层长按轮盘作为必学操作。我们只有三名队员，第一版采用固定面板更容易解释与验证。
   - 来源：[Feral 官方操作 FAQ](https://www.feralinteractive.com/en/faqs/companyofheroes/1.0.2/ios/)，本轮已读取。
2. **Door Kickers**：官方明确是可自由暂停的实时战术。借鉴把思考与执行分开的节奏，不要求手指追赶战斗。我们的具体“预览后确认”是本项目提案，不声称该游戏使用完全相同手势；也不因此引入战中改令。
   - 来源：[KillHouse 官方游戏介绍](https://inthekillhouse.com/doorkickers/)，本轮已读取。

不推荐虚拟摇杆作为默认：三人轮流操纵容易变成走路劳动，不能直接表达高点、搜集、射界等战术目的。自由画路径、手势轮盘可后续研究，不和基础操作一起上线。

## 3. 推荐操作：选人 → 点目标预览 → 固定按钮执行

| 意图 | 新默认操作 | 防误触边界 |
| --- | --- | --- |
| 选队员 | 点底部三张固定头像卡 | 仅选人；不靠长按触发技能，不顺带移动。第一版保留头像选人，不增加拥挤人物本体抢选。 |
| 看地图 | 战场单指拖动平移；双指缩放/平移 | 即使从人物身上起拖也只动镜头；一旦认定拖动/双指手势，直到所有手指离开都不产生世界命令。 |
| 移动 | 点空地显示落点与真实路线；按固定的“移动到这里” | 预览不移动、不改资源。再点别处只更新预览；走/跑用明确开关，默认走，不再靠按多久。 |
| 搜集 | 点箱子，底栏显示物品、接收队员与“前往搜集” | 不需要精确戳浮动小按钮；重复按不重复领取。范围、背包与搜索完成条件仍走权威规则。 |
| 占高点/掩体 | 点位置显示路线、最终站位与保护方向，按“前往占位” | 只能沿合法入口到达，不因确认而瞬移。对象重叠时显示固定选择条，不猜测玩家意图。 |
| 改朝向 | 点固定“朝向”，再点要看的方向；看射界后确认 | 仅明确朝向模式下接受方向预览；拖地图仍平移。取消还原草稿，不改变已提交朝向。 |
| 工具 | 点“装备/工具”选物品，点目标预览范围，再确认 | 不可用原因写清；取消不耗物品。隐藏的头像长按操作改为可见入口。 |
| 发动伏击 | 独立入口打开三人准备摘要，再按“发动伏击” | 与普通移动确认分离；提示“开战后自动执行，不能移动”。不能因上下文按钮改名而连点开战。 |

这是本提案对设计 v2 第 8 节的细化与部分替代建议：改用单指稳定平移、显式朝向模式与固定动作面板。**未采纳前不修改 v2 的已确认状态**。SCOUT → ALERT → SWEEP、ALERT 冻结与只读复盘保持不变。

### 画面与反馈

- 底部左侧固定三张头像；右侧固定当前动作卡、取消和确认。地图上的箱子/掩体标签只负责识别，不承载漂移的执行按钮。
- 移动预览显示选中队员编号、虚影落点和路线；实际移动另用明确状态。颜色之外同时用线型、箭头和短文字区分。
- 朝向模式仅突出当前队员的方向箭头与真实可打目标/遮挡信息，退出后收起辅助信息。不把方向扇形冒充完整命中保证。
- 确认按钮始终显示具体动词，不只写“确定”。按钮按下后锁定对象和动作；失效时取消并解释，不偷偷替换目标。
- 主触控区先以约 56dp 级作为原型目标，留足间隔；需实际换算 Android 显示缩放和安全区，不把 Godot px 当 dp。折叠屏内外屏独立检查。

### 取消、移动中与阶段切换

- 未确认的是草稿：切队员、切阶段、打开模态框、返回键或触摸取消时清理；不留下会在下一次抬手执行的旧命令。
- 已开始移动时显示“停止”，不提供回滚拾取/资源的万能撤销。精确停止规则在执行切片中声明并测试，不能侵入 ALERT。
- 有草稿时不直接发动伏击：提示先确认或取消草稿；不默默提交。
- 准备摘要只是防误触确认，不新增“缺弹必须禁止开战”等平衡规则。
- 预览和确认之间世界可能变化：确认时重新验证路径、占位、距离与资源；失效则不执行，并保留可理解的原因。
- “前往搜集”需绑定具体队员/箱子。现有邻近自动搜索行为必须审计，避免其他队员先自动取走使预览承诺失真；搜索时机契约如改变，独立声明与验证，不夹在纯 UI 改动里。

## 4. 代价与不做的事

代价是每次下命令多一次确认。对本作低频三人布置，预计值得用一次点击换确定性；这是待试玩验证的判断，不是已证明减少误触。选人、镜头、打开背包不增加确认，防止全部操作都变慢。

不改战斗结算、弹药预算、敌人波次或存档；不加入战中微操、全套命令队列、自动最优站位或摇杆控制。先证明基础命令不误发，再考虑快捷模式。保留桌面键鼠既有操作，触屏改动不得透传为重复鼠标命令。

## 5. 建议插在 M2-B2 前的小切片

命名为 **M2-T**，避免和旧 M1-B2 设备补验混淆。B2 的单次接触/爆破解方向保留，建议先完成触屏原型；当前只暂停推进以讨论方案，不宣称已获实施批准。

1. **T1 手势归属与取消**：建立一次触摸只有一个拥有者的输入路由；覆盖 UI、点击候选、镜头拖动、双指和取消。修复朝向松手落入移动路径；暂不同时改弹药或地图。验收真实输入序列而非仅直接调用命令函数。
2. **T2 固定动作卡与移动/占位草稿**：点地只预览，明确确认；头像仅选人、取消和对象重叠选择。预览与执行共用路径/合法性查询，桌面行为单独回归。
3. **T3 搜集、朝向、工具与开战确认**：各动作共享草稿/提交边界；搜集目标绑定的契约变化单独测试。工具取消、冻结、重试和资源守恒继续通过。
4. **T4 触屏体验验收**：同版本录屏与误触记录，内外屏及初次玩家验证；根据证据决定是否恢复 B2，不把桌面合成事件当真机通过。设备暂缺可做桌面原型，不取消最终设备门。

各切片单独提交、隔离测试、记录精确源码版本。外部 GPT 在原项目对话做真实 PLAN/REVIEW；本轮未取得新外部反馈，状态为**待外部评审**，不继承旧批准。

## 6. 验收目标（未执行）

- 回放至少 100 次不同起点拖镜头、50 次双指/交替抬手序列：世界命令计数为 0。
- 至少 30 次朝向编辑/取消：非明确移动确认产生的移动为 0；取消后朝向/资源无变化。
- UI 按下拖出、按住时刷新、连点、第二指加入、后台/恢复、系统取消、切队员/切阶段：无穿透、无旧目标提交、无重复消费。
- 预览后路线堵塞、箱子已空、格子被占、满背包：确认失败可解释，不偷偷改目标；工具与弹药继续满足守恒。
- 场景 1×/2×、冻结、失败重试和 B1 资源定向回归通过；六关完整 smoke 仍是独立待补门，不能用新输入测试替代。
- 真机先记录同一组“搜集→占位→朝向→发动”任务的旧版基线，再比较新版误发命令、求助次数和完成时间。设计目标：5 名新玩家至少 4 名独立完成，误发命令比例低于 5%；小样本只用于迭代，不宣称统计证明。附原始计数与失败样本。

| 字段 | 值 |

---

## 1. 背景

单夜循环是「侦察/搜集 → 布阵 → 等待 → 起爆 → 清场搜尸」。张力来自**第一枪的时机**：早开火漏掉后续进场的敌人（如 4 s 侧翼），晚开火可能被先发现或前队走出杀伤区。

旧契约 `SCOUT → ALERT → SWEEP` 与「等待阶段可微调」存在歧义：ALERT 由谁触发（玩家手动、预设条件、敌人越线、倒计时）未写死。定位页已定（2026-10-16）：**布阵阶段设条件，到点按计划自动执行**；手动起爆、越线触发为备选，不作默认。

工程现状（`plan_state`、现有 ALERT 锁定）只作参考，不约束本 ADR。

---

## 2. 决策

1. **默认起爆路径**：玩家在布阵阶段为小队选定**一个**起爆条件；进入等待后模拟推进，条件满足的那一刻进入起爆（计划自动执行）。
2. **默认可选条件类型**（VS 必须支持，布阵 UI 可从中选一）：
   - **看到第一个敌人**：指定单位（或「任一队员」）的杀伤区内首次出现存活敌人。
   - **地雷响**：指定地雷完成触发（爆炸瞬间）。
   - **越过标记线**：指定敌人（默认「主纵队头兵」或「任一敌人」）越过布阵时放置的标记线。
3. **手动起爆为备选，不作默认**：等待/起爆阶段仍保留「起爆」控件（与暂停、倍速并列），玩家可随时强制进入起爆；**新开局不预选手动**，也不把「无条件纯手动」当作推荐方案。
4. **ALERT 与等待的关系**：
   - **等待**＝敌人行军接近、计划未锁定开火；仍可有代价地微调。
   - **起爆**＝条件满足（或手动）后，全队按计划开火；此后不再改站位/朝向/条件。
   - 旧名「ALERT」在 VS 中等同「进入起爆」；若 ADR-ALERT-01 的**全图警报**触发，则强制提前进入战斗（敌人改战斗队形进场），视为非计划起爆，**标准伏击不可得**。
5. **全队起爆前保持静默**：条件未满足前，队员不开火、不主动暴露（地雷触发本身即起爆事件）。

## 3. 规则细则（含初值）

### 3.1 条件配置（布阵）

| 项 | 初值 / 规则 |
|----|-------------|
| 每局起爆条件数 | 恰好 1 个（全队共用一个「首枪」触发） |
| 默认类型列表 | `see_first_enemy` / `mine_detonate` / `cross_marker` |
| `see_first_enemy` 绑定 | 默认绑定方案关键射手（方案 A：MG42；方案 B：地雷优先用 `mine_detonate`）；可改绑任一队员 |
| `mine_detonate` 绑定 | 必须已放置至少 1 枚地雷；绑定指定地雷 id |
| `cross_marker` | 布阵时在网格上画一条线段（两端吸附格心）；默认检测「任一敌人」中心越过该线 |
| 未设条件时 | 布阵结束校验失败，不可进入等待（强制选手动备选或上述三者之一） |
| 手动备选启用方式 | 显式选择条件类型 `manual`；或等待中点「起爆」强制触发（即使已设其它条件） |

### 3.2 等待阶段

| 项 | 初值 / 规则 |
|----|-------------|
| 时间模型 | **实时推进**（规划推荐默认；可暂停、1×/2×/4× 倍速）；倍速不改变条件判定结果 |
| 微调 | 允许改站位/朝向；在岗哨视野内挪人按 ADR-ALERT-01 累计发现；挪位耗时按移动规则结算 |
| 条件求值频率 | 与模拟同为固定 20 Hz tick；条件在 tick 边界判定 |
| 静默 | 起爆前队员武器不射击；环境音压低（表现层） |

### 3.3 起爆瞬间

| 项 | 规则 |
|----|------|
| 进入起爆 | 条件首次为真的那个 tick，或玩家按下手动起爆 |
| 计划锁定 | 站位、朝向、武器、杀伤区锁定；不再接受布阵类输入 |
| 控件 | 仅保留：起爆（若尚未起爆）、暂停、倍速 |
| 标准伏击相关 | 「起爆前未被发现」＝进入起爆的 tick 之前，警报档位从未达到「区域警戒」或「全图警报」（见 ADR-ALERT-01；精确定义以复盘日志字段为准） |

### 3.4 与侧翼延迟的关系（院子初值）

- 主纵队进门后 **4 s** 侧翼从东巷进场（规划 D.1）。
- 条件若在侧翼进场前满足 → 早起爆：侧翼可能未进杀伤区，复盘主因应为「起爆过早」。
- 条件若过晚满足 → 前队可能离开杀伤区或已被发现。

---

## 4. 不做

- 不做「无条件、纯倒计时自动开火」作为默认路径。
- 不做多段链式条件（如「先地雷再 MG」脚本树）；VS 只支持单一首枪条件。
- 不做 Command Mode 式多步编排到关卡通关。
- 不做起爆后改站位/朝向的全图微操。
- 不把手动起爆设为新局默认选项。
- 不要求本 ADR 迁就现有 `plan_state` 实现细节。

## 5. 验证用例

| ID | 场景 | 期望 |
|----|------|------|
| T-01 | 方案 A：条件 = MG42 `see_first_enemy`；主纵队头兵进入 MG42 杀伤区 | 该 tick 进入起爆；日志有 `trigger=see_first_enemy` |
| T-02 | 方案 B：条件 = `mine_detonate`；敌人踏雷 | 地雷爆炸 tick = 起爆 tick；首事件为地雷 |
| T-03 | 条件 = `cross_marker`；头兵越线，侧翼尚未进场（相对最佳 −4 s） | 进入起爆；侧翼未在杀伤区 → 逃脱或复盘主因「起爆过早」 |
| T-04 | 同 T-01，但最佳时刻 +4 s 才满足（或手动拖晚） | 前队离开杀伤区或发现风险上升；复盘主因「起爆过晚」类 |
| T-05 | 已设 `see_first_enemy`，等待中提前点手动「起爆」 | 立即进入起爆；日志 `trigger=manual`；条件未满足亦生效 |
| T-06 | 布阵未选条件直接点开始 | 被校验拦截，不进入等待 |
| T-07 | 1× 与 4× 倍速跑同一计划与条件 | 起爆 tick 与事件日志哈希一致 |
| T-08 | 全图警报已触发后再满足原条件 | 已处于战斗进场；标准伏击判定失败；不要求再走「安静等待→条件起爆」路径 |

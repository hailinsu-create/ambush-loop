## 契约

- `plan.operators[i]` 可选：`climbing:true`、`climb_from:{x,y}`（出发格）、`climb_ticks_left`（缺省 `round(CLIMB_COST_S*TICK_HZ)`＝40）；`x,y`＝目标格。`CLIMB_COST_S` 从此真正被使用。
- 攀爬期间：运行位置＝出发格、tier ground、不能开火、暴露按出发格 ground 档（无 ×1.5 剪影）；结束：位置＝目标、tier＝目标格档位、可开火。上/下通用。
- tick 顺序：1 输入/转向冷却 → **1.5 `_step_climb`** → 2 移动 …；`climb_end` 出现在 tick 39（tick 0..39 共 40 次递减）。
- tick 0 事件顺序：`sim_start → mine_place → climb_start* → phase(wait) → alert_change(scout_carry)`。
- `schema/events.json` type 枚举追加 `climb_start` / `climb_end`。
- fixture plan A/B 不带 climbing → **金标不变**（W2 原 74 条全过；测试另验无 climbing 计划 0 个 climb_* 事件、hash＝金标）。

## 控制器 / UI（与规划差异）

- **差异**：规划写的是放置时在 `_move_selected_op` 写攀爬字段；实际是在 `_start_wait` 里由 `_apply_climb_to_plan()` 统一打标（站在 high 格的 op → climbing），这样点按、拖放、预设、脚本放置都走同一条路径，撤销后也不会留下旧字段。地面 op 会清掉这些字段。
- 出发格 `_climb_departure_cell`：目标格 8 邻域里可走的地面格，取离 `squad_insertion[0]` 最近的一格。
- 放置反馈：「· 高点 · 开局先攀爬约 2 秒，期间不能开火」；开局提示「N 人攀爬中（约 2 秒，期间不能开火）」（不含黑名单词）；肖像卡状态「攀爬中」，爬完消失；地图上攀爬中的 op 画一个旋转弧加「↑」（没有新增资产）。

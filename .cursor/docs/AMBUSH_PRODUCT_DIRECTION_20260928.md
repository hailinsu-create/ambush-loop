## 用户明确的目标

参考用户提供的 [Bilibili 合集](https://space.bilibili.com/352319684/lists/772847?type=season)，做具有《盟军敢死队 2》战术体验的原创游戏，将体验短程化、关卡化，核心为：

**搜集弹药 → 占领高点 → 埋伏 → 歼灭。**

本次网页读取未成功，未观看或逐段分析合集。这里对参考体验的理解来自用户上述描述，不冒充视频分析；视频里的具体关卡、操作和镜头仍待核实。

产品定位：安卓横屏、离线、短关卡小队伏击。玩家通过资源分配、抢占有利位置、安排射界和开火时机，获得以准备换取战斗优势的体验。四个环节要有因果关系，不能只是依次点亮的任务提示。

## 四个环节各自需要产生的决策

| 环节 | 玩家要做的决定 | 要看到的结果 | 验收反例 |
| --- | --- | --- | --- |
| 搜集弹药 | 拿哪种武器、是否绕路补给、弹药交给谁 | 拾取和分配改变可用战术与持续火力 | 每局机械搜完所有箱子，拿什么都一样 |
| 占领高点 | 谁占有利位置、覆盖哪条通道、谁保护侧翼 | 位置的观察/射界优势清楚，同时存在侧翼或覆盖盲区 | 只是画面抬高，战术没有变化；或全队挤一处就能赢 |
| 埋伏 | 等目标进入哪片区域、怎样交叉覆盖、何处放工具 | 开火条件与覆盖预览可读，等待确实换来优势 | 见敌即打和等入伏没有可解释的差别 |
| 歼灭 | 判断计划是否覆盖目标、弹药是否足够 | 战斗简洁、有爆发感，结果能解释准备的价值 | 靠固定隐藏解通关，失败只能猜 |

歼灭后的搜刮和撤离服务于本关收尾或必要的下一波；波次数量不作为内容量指标，避免重复相同准备。

## 对现有原型的处理

现有 README 记录了搜刮背包、移动和掩体部署、开火条件、自动伏击、波间补给及撤离，具备承接方向的基础；文档描述不等于当前版本已通过真机验收。

“高点”列为优先核实的玩法缺口。本次仅在 main.gd、grid.gd 和 COMMANDOS_RAID.md 中做了关键词检查，不能据此断言全工程不存在高度机制。实施前继续审计地图、掩体和战斗结算，再决定最小改动。

首个原型提案：在院子已有地图框架内设计一个可读的制高位置，以明确射界和侧翼弱点验证价值。不在本次文档修订中新增楼层、攀爬、通行几何或伤害加成。若现有规则不足以体现用户要的高点体验，另列玩法切片、更新计划和回归基准，不能把装饰平台算成功能完成。

战斗控制暂按现有契约：准备期控制小队，ALERT 锁定计划，自动执行伏击。用户本次未明确要求改为战斗中实时微操，因此不把“参考盟军敢死队 2”解释为已授权全面替换控制系统。

## 首个样板关提案

用现有第一关“院子”承载完整四步，不扩关卡数量：

1. 简报展示目标通道、有利位置和可见补给，让玩家先形成一个小计划。
2. 以少量必要补给建立第一次武器/弹药分配，控制无决策的走路时间。
3. 一名队员占据制高位置，其他队员补足侧翼与近距离覆盖；地图应支持可解释的替代方案。
4. 设置入伏条件和工具，确认覆盖后发动伏击。
5. 显示歼灭或失败的真实原因；失败后快速回到准备，保留可用情报和上次计划。

首次提案以熟悉后的单关 3–6 分钟为试验目标，不是用户指定时长、现有测量结果或宣传承诺。实际首通、重试、准备和等待时间分别记录，再确定节奏。

## M1/M2 与后续规划的调整

- M1：保留 R45–R53 已有版本映射与在制工作；检查每项提示是否帮助玩家理解四步循环。不因方向补充把未完成切片写成已完成，也不将提示文字当玩法本体。
- M2：第一关验收增加“资源—位置—时机—战果”的因果闭环与高点价值验证；既有安全续玩、失败反馈、触控和盲测要求保留。
- 高点若需要改变模拟，单独实施与验证，明确更新受影响规则和参考结果；不得混进 R45 文案修补。该新增范围需重新评估旧工期估算。
- M3：在样板通过后推广到现有六夜，每关突出不同战术问题，避免六张图重复同一站位解。

M2 的实际验收补充：

1. 玩家能说明自己为何拿这份弹药、交给哪位队员。
2. 玩家能指出制高位置覆盖的通道和至少一个弱点。
3. 至少一次对照验证：保持其他条件尽量一致，改变分配、位置或开火时机中的一项，得到可解释的结果差异。
4. 关卡至少有两种经实际验证的有效准备方案，避免只有隐藏参考脚本能赢。
5. 失败反馈引用真实事件；重试不要求重复冗长教学或无选择的搜刮。

以上均为待验收要求，没有新增测试通过结论。

## 目标与契约

院子默认画面突出一句任务、一组三人卡、选中队员状态和一个主动作“开始交战”。战术视图可展开路线、时间轴、参考射界和其他技能。青色离散覆盖仍使用已接入的真实目标几何；它表示有射线，不保证弹药或开火许可。

准备、交战、战后整理、复盘继续使用现有权威处理入口。冻结位置、装备、朝向及确定性结算不变；观察层开关只改变显示。补给数量、武器数值、两波结构和重试资源重置留给 B/C/D 独立切片。

失败卡显示真实逃逸事件中的目标、路线、时刻，以及三名队员对该目标最近的射击/受阻记录。最近记录可早于逃逸，明确保留它的时间，不误称“逃逸瞬间原因”。作者建议只在“记录与建议”里出现，改为“可以尝试”；新增直接进入只读时间轴复盘的可点击入口。

当前“重新部署”仍恢复计划并重置资源，按钮提示明确需要重新搜集武器/弹药；尚未交付 M2-D 的快速检查点重试。

## 实现范围

- 新 `ui/yard_hud.gd` 负责院子展示与短文案，调用既有命令函数；不自行走位、补给、改血量或写战斗事件。
- `main.gd` 接入关卡限定的展示开关、真实失败记录及恢复时默认折叠；隐藏重复栏，保留选中队员真实覆盖，默认仅强调当前/预览掩体的保护范围。
- `operator.gd` 使方向参考的显示开关在重建时持续生效，视线/射击资格函数不变。
- `c2_director.gd` 在院子桌面镜头把三人卡放到左下，触控沿用已有卡槽；切换其他关卡恢复旧展示。
- 新 `m2_yard_hud_gate.gd` 复用 M1-I 的实际搜集与坡道移动夹具，注入真实鼠标/触控 GUI 事件，验证非穿透、冻结、实际胜利/逃逸及复盘。
- Windows/Linux 隔离包装器允许新 gate；共享 smoke 中与新界面相关的断言改为展开战术层后检查观察环，并核对新的失败事实和触控行动文字。共享 smoke 本轮仅编译检查，未运行全量。

## 已发现并修正的问题

首个运行 `0fc8446fe0f64591b47c32b51e08538a` 因 GDScript 对动态日志返回值不能推断类型退出 1，已给展示变量加明确 String 类型。隔离守卫确认玩家数据不变。

运行 `9e76fea578d24581a49ee3163f90312e` 图形 gate exit 0，首次完成鼠标/触控、冻结、真实胜利与失败。随后目视发现触控顶部提示重叠、失败页需要独立复盘入口，已修正。

运行 `87645c6f1c1f42ee9b9837689c2bfaa9` 新复盘入口及真实 GUI 验证 exit 0。目视又发现选中状态被触控底板压暗，已调整其所属显示层，重新验证后的截图才作为最终证据。

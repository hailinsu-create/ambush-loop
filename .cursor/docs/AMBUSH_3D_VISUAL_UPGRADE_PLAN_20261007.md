## 1. 目标：打开就像一处可以伏击的真实地方

采用原创、风格化写实的工业夜袭微缩战场：固定斜俯视、可信的建筑体积、清楚的三人剪影、冷灰蓝环境与少量暖色工业灯。用高台、门洞、侧巷和掩体形成可读的伏击空间。玩家远看能理解路线，近看能看到材质和人物动作。

目标画面：仓库墙面有砖石与金属包边；高台有厚度、坡道有接地阴影；补给角由暖灯和有辨识度的箱体提示；侧巷更暗但敌人仍清晰；开火瞬间有枪口、后坐与目标受击对应。战场占据屏幕主体，信息随选中和操作出现。

截图反映的直接问题：平铺方格地面、大片同灰墙体、人物尺度偏小、信息面板和引导文字占据较大面积；该次镜头偏移后还出现大量空背景。先解决构图、体积、比例和信息层级，再增加小物件。

保持三人、六关、搜集→占位→埋伏→歼灭的玩法；视觉层不改变格子、合法坡道、LOS、库存或冻结交火。建筑装饰不增加未经声明的阻挡。排除开放世界、自由环绕相机、可破坏建筑和全套战斗重写。

## 2. 画面升级内容

| 模块 | 具体交付 | 玩家能直接感到的变化 |
| --- | --- | --- |
| 构图与相机 | 默认斜俯视和缩放标尺、按有效战区限制平移、回中适配安全区；关键区域保持可见 | 打开游戏就看见战场，人物与操作目标足够大，少空白和遮挡 |
| 场景结构 | 仓库门立面、装卸高台、坡道、连续墙角、侧巷、补给角、撤离口七组模块；统一倒角、厚度、比例 | 从规则方块升级成有用途、有层次的工业院子 |
| 地面与材质 | 混凝土/砖墙/涂漆金属/木材四套主材质；边缘磨损、排水沟、道路涂线、少量污渍 | 地面不再像棋盘，同一颜色下仍能分清材质；装饰密度集中在边缘 |
| 灯光 | 统一曝光、冷暖分区、静态光照/AO候选、角色接地阴影；灯具外观和局部亮区配套 | 高台更立体，人物站得住，夜景清晰而有气氛 |
| 人物 | 三名原创队员和两类敌人外观；统一骨架、武器握持点、背包和轮廓差异 | 一眼辨认角色和枪口朝向，替换积木式人物观感 |
| 动画 | 待机、移动、转身、搜索、瞄准、射击、命中、倒地；坡道步态与脚底接地 | 移动、停步、开火连贯，搜索和中弹有可见反馈 |
| 战斗效果 | 枪口短闪、命中火花/尘土、有限弹道、轻量爆炸、短烟；事件驱动与对象池 | 看得出谁开火、打向哪里、是否命中，伏击更有爆发感 |
| 战术与 HUD | 选中轮廓、细线射界和路线、图标化短卡、可收起引导、就近确认；设置移入二级页 | 画面留给战场，信息仍完整，操作区与装饰明确分开 |

普通视图只显示当前决策相关信息；战术视图保留完整查询。敌我还用轮廓/形状区分，不能只靠红绿。角色被前景挡住时先用已知单位的轮廓/顶部标记；屋顶分段隐藏作为单独候选，不能暴露未知敌人或改变真实射线。复盘动作仅使用已有记录；缺字段维持明确静态姿态，不伪造历史开火。

## 3. 技术选择与初始预算

这些是实施起点，需要 V0 实测后修订；不是现有性能报告或硬件保证。

- 手机保留 Compatibility 基线，用相同院子、同分辨率、同操作轨迹对照 Mobile。依据正确性、稳定性、热态帧时决定默认；不直接把桌面 Forward+ 配置搬到手机。
- 静态细节优先进入共享材质、图集和烘焙纹理；LightmapGI 在固定 4.7.2 和目标设备验证后采用，失败时使用材质 AO/顶点色与简化照明。处理烘焙 UV、内存和动态角色接光，避免只验证静态截图。
- 首轮人物 LOD0 每人约 3k–6k 三角形、1–2 个材质槽；普通道具 200–1500 三角形，主要建筑按模块控制。远景简化，默认镜头不为看不到的面部细节耗费预算。
- 标准档初始可见场景目标：约 150k 三角形以内、3D 绘制调用约 150 次以内；测量包含阴影与透明通道，另报 UI 成本。纹理通常 512–1024，核心共享图集至多 2048；纹理与光照图运行时驻留预算先按 128 MiB 规划。超出须附收益/帧时证据，低于也不自动代表流畅。
- 主光至多一套有限范围实时阴影；局部灯优先烘焙或无阴影。低档保留角色接地提示。枪口亮光不为每个子弹创建动态灯；粒子、弹痕、尸体表现都有场景上限和清理条件。
- 同类道具复用网格与材质、适当批量绘制；不把整张地图合成一个无法有效剔除的巨大对象。减少透明叠加，烟雾不覆盖操作目标。
- 不把实时 GI、体积雾、屏幕空间反射、景深、运动模糊作为手机基础观感依赖。湿润质感先用粗糙度和少量反射提示，不铺全屏反光水面。
- 低/标准/高三档保持同一场景设计和战术信息。可降低阴影、粒子和 3D 内部渲染分辨率；UI 独立保持清晰。60fps 是设备验证后的可选目标。

依据：Godot 官方[渲染器比较](https://docs.godotengine.org/en/4.7/tutorials/rendering/renderers.html)列出 Mobile/Compatibility 与桌面 Forward+ 的适用范围；[3D 性能指南](https://docs.godotengine.org/en/stable/tutorials/performance/optimizing_3d_performance.html)和[GPU 优化指南](https://docs.godotengine.org/en/stable/tutorials/performance/gpu_optimization.html)支持共享资源、控制绘制与透明叠加成本。上述具体预算为本项目建议，不是官方限值。

V0 与 V1 的离线造型/风格制作可并行安排工作；运行时加料必须受 V0 数据约束。V1 的可玩画面确定后才批量制作 V2/V3，避免做完全部资产才发现人物过小或风格不统一。每个 V 切片继续拆成可回退的小提交，提交前核对影响范围。

第一可见里程碑为 V1：不是再加几个箱子，而是同一镜头下构图、墙体、高台、灯光、人物比例和 HUD 同时形成明显提升。第二里程碑 V2–V4 是完整院子；第三里程碑 V5 才允许推广 M3。V0 结束后给滚动工时估算；人物重拓扑/绑定/动画与手机热态调试是主要不确定项，不承诺六小时整套完成。

## 6. 验收标准

画面：同一个游戏内镜头比较旧/新，包含默认缩放、近景、低档、射界打开、交火峰值和复盘。目标是五个地标、三名队员、两类敌人可辨；默认静态 HUD 占用先争取 ≤25% 可用画面且不牺牲真实触控尺寸，展开/模态单独统计。手机正常亮度下高点边缘、敌人和射界仍可读。用户艺术评价与五人首局门仍需真人，不能由截图自动断言。

性能：继承标准档30fps目标、中位帧间隔≤33.3ms、p95≤40ms、p99≤66.7ms；非加载区无连续三帧>100ms。代表轨迹至少10分钟，并做30分钟热态运行，按每5分钟分段而非用总平均掩盖后期卡顿。分段记录错过帧比例、最长卡顿、内存、节点/资源、温度及可用CPU/GPU指标。

长稳：20次失败恢复/复盘返回，无崩溃、ANR、LOW_MEMORY；第10次后稳定检查点与第20次比较，PSS增幅建议≤10%且节点/资源数量达到平台，不能有持续增长。准备恢复≤5秒；输入到预览/确认反馈p95≤67ms，较重路径反馈≤100ms。固定设备、画质、渲染器、分辨率、操作路线及充电状态记录，重采样确认，不以截图或短时FPS代替。

正确性：纯画面升级维持两种打法结果、权威位置/LOS、拾取、资源守恒、冻结和只读复盘；显示隐藏/质量切换不能影响模拟。相机/HUD改变要覆盖双指、取消、边缘、安全区和至少约48dp实际有效触区。隔离包装器保留旧红灯，核对引擎/包装器退出、运行时错误和玩家数据不变。

构建：每个候选记录源码SHA、严格递增构建身份、APK SHA、设备和渲染器。当前已知构建曾复用版本号，不能仅据0.6.29判断手机源码；安装前核实签名及包身份。修正测试截图可能进入APK的导出卫生问题，保留原测试证据。

# M3 前：3D 主玩法院子质量计划

日期：2026-10-06。依据用户真机反馈：3D 缺射界等信息、卡顿、画面简略、确认位置不便，并明确以后以 3D 为主要方向。

状态：3D 主方向已由用户确认；本文具体交互、性能预算和工作量经外部 GPT 规划评审。P0 正在执行：smoke 相机平移前置修正 `6f9a6dc` 已获实际 GPT 源码批准，完整隔离回归正在运行并已通过原平移失败点。生产功能基线仍为 `0f53512`，3D 新功能及手机性能采样尚未实施完成。当前进展见 [P0 修复与评审记录](AMBUSH_P0_RECOVERY_20261006.md)。

## 1. 决策与阶段边界

在 M3 六关推广前，插入 **M2.5：3D 院子质量阶段**。它承接 M2 未闭环项，不通过新编号宣布旧 M2 完成。目标是玩家不切回 2D，就能观察、搜集、占位、调朝向、交战、复盘、修改并重试。

3D 成为正式主界面；2D 留作开发比对/兼容回退，不再并行追加一套独立产品功能。默认 3D 的开关在信息、操作和性能门通过后启用，最终玩家不再需要点“查看 3D 院子”才能体验主产品。

保留同一个逻辑网格、合法坡道、真实射线、库存和固定 tick 战斗。3D 负责表现、镜头和拾取映射；不引入第二套物理命中规则。SCOUT → ALERT → SWEEP、交战期冻结部署、只读复盘保持。新增战术规则必须另列变更和反例。

本计划替代设计 v2 §7.1 的烘焙/2D 优先路线、旧整合计划的 3D 仅预览/长期可选定位，以及 §8 固定右下确认的交互方案。其他规则、六关范围、隔离和发布门槛继续有效。M3 是把合格样板推广到五关，不提前填充六套低质量场景。

## 3. 先把战术信息搬进 3D

默认仅显示选中队员的信息，避免三层射界覆盖全场。战术视图再展开全队覆盖、已知主路/侧翼入口、逃逸线、可达高点与坡道。标签用形状、短文字和颜色共同表达。

必须补齐的功能对照：

| 信息/操作 | 3D 交付要求 | 验收重点 |
| --- | --- | --- |
| 射界/射程 | 选中队员的朝向、角度、有效距离，高低地投影清晰 | 与同一武器参数和真实 LOS 查询一致；墙后不可射部分有断线/遮挡说明 |
| 可射/不可射原因 | 对具体目标显示射界外、距离、墙/高度遮挡、弹药、开火许可 | “可射”只代表当前条件，不承诺未来必杀；反例逐项验证 |
| 预览位置和朝向 | 移动预览带幽灵角色与拟议射界，确认前不修改权威状态 | 路径、朝向、覆盖同时可读，取消后无残留 |
| 路径/高点 | 路线贴合法表面，高台/坡道上下连续；高度用可读边缘标记 | 不能让地面投影穿墙或隔空上台；高低点选中一致 |
| 选人/补给/工具 | 人物选中环、箱子搜索进度、弹药变化、手雷预览、当前工具状态 | 装饰不可抢点击；重叠目标有小选择条；资源只在真实执行时变化 |
| 战斗/复盘 | 目标、开火、命中、逃逸事件可定位；同一时间轴和返回结果入口 | 回放不写实战状态，切换/拖轴/恢复不会增加资源或丢失角色 |

建立共享的战术展示数据接口，2D 与 3D 消费同一批查询结果。射界网格在位置、朝向、装备、遮挡版本变化时更新；不要每帧给全队重做全图射线。粗略扇形与精确可射判定须在界面上区分，不能用一个好看的完整圆锥冒充实际可射区。

## 4. 操作方案：缩短手指移动，保留明确意图

首选流程：点队员 → 点目的地看路线 → 目的地附近显示“移动到这里 / 取消”短条 → 确认后执行。补给箱显示“前往搜索”，同一操作链自动寻路并开始正常搜索，搜索仍可被打断，不直接发资源。

确认条靠近目标但偏离落指点，限制在安全区内，避开角色、路径、底栏和系统边缘。先用 56–80 逻辑像素偏移作为实验值，再按真实手指遮挡调整；按钮实际有效区域以 Android 显示缩放/密度验证至少约 48dp，不把 Godot 48px 当作 48dp。

触摸抬起后才显示新确认条，必须另一次触摸才能执行；生成该预览的同一次 release 不能落到新按钮上。出现后位置稳定，直到意图取消或目标变更；镜头手势开始时隐藏并取消预览。确认绑定 actor、目标、工具、阶段和意图版本，切人/切阶段/返回/后台一律失效。取消永远不耗资源。

朝向用队员附近的独立方向手柄：拖动时显示射界，松开在合法状态提交；按住期间只拥有朝向输入。保留左右微调作为辅助。普通地图拖动和方向拖动必须通过起点归属区分，不能都触发移动。

双指平移/缩放只操作相机，抬起后不产生落点指令。默认固定斜俯视，提供一键回中；首轮不做自由环绕旋转，待遮挡与拾取稳定后再评估 90° 分档旋转。

设置提供“就近确认（默认候选）/固定拇指区（可选）”和左右手布局；发动交战/撤离保留固定易找主按钮，与移动确认使用不同形状及文案。背包、档案、复盘细节收在二级界面；现场只留必要状态。先实测最常用 3 项操作，再扩可配置项。

## 5. 流畅度：先测量再加画质

同 APK、同场景、同录制指令，在荣耀真机测准备/平移缩放/战术叠层/交火峰值/复盘拖轴/连续重试。记录分辨率、实际渲染器、画质、CPU/GPU 可得指标、帧间隔分位数、绘制调用、内存、温度/降频、冷启动和 3D 首次切入。使用 Perfetto/系统帧呈现等可用数据与 Godot 监视交叉核对；没有 GPU 计时就明确缺项。ADB 截图或平均 FPS 不能单独证明流畅。

本轮建议出口预算（非现状数值）：

- 默认标准档稳定 30fps；代表性 10 分钟轨迹，每段稳态 p95 帧间隔 ≤40ms、p99 ≤66.7ms，非加载区不出现连续三帧 >100ms。支持更强设备选 60fps，60 档另立预算。
- 标准档先稳定，低档降低 3D 内部分辨率、阴影/特效，不降低 UI 清晰度或战术信息完整性。手机当前 Compatibility 与候选 Mobile 渲染器先做相同镜头 A/B，依据设备支持与数据选择。
- 30 分钟运行及 20 次失败恢复/复盘返回无崩溃、ANR、LOW_MEMORY；相同稳定检查点的 PSS 与节点/资源数量无持续上升。10 次恢复后取稳定基线，20 次结束后 PSS 增幅建议 ≤10%；异常需解释或修复，不能仅以未崩溃通过。
- 准备恢复控制继续 ≤5 秒；正常操作可见响应 p95 ≤100ms（量测输入到下一可见反馈），加载另计；冷启动与首次 3D 加载分别报告，不隐藏卡顿峰值。

按测量排序优化：暂停隐藏的纯 2D 绘制/特效工作但保留模拟 → 展示状态脏标记/固定 tick 更新与插值 → 事件游标/按 tick 索引及缓存，避免反复扫全部日志 → 材质和对象复用 → 控制透明叠层填充、阴影距离与更新 → 静态批处理、纹理图集、模型 LOD → 分阶段加载。现有 MultiMesh 和 FX 上限保留并检查实际收益；表现降级不可改变胜负或输入。

技术参考：[Godot 3D 性能优化](https://docs.godotengine.org/en/stable/tutorials/performance/optimizing_3d_performance.html)、[GPU 优化](https://docs.godotengine.org/en/stable/tutorials/performance/gpu_optimization.html)。这些指导强调测量、批处理与渲染成本；具体支持仍以固定 Godot 4.7.2 和手机实际渲染器验证，不照搬 latest 的新特性。

## 6. 美术：工业微缩战场，先做一张能玩的完成图

方向：风格化写实的斜俯视 3D 微缩战场。先让墙、坡道、台面、枪口和敌我轮廓一眼可读，再增加材质细节。清冷环境光配少量暖色工业灯，降低泛黄和全场同灰；不靠全屏压暗制造夜景。

先完成院子 1 个固定标准镜头：仓库门、装卸高台/坡道、侧巷、补给角、出口五个大地标。把逐格方块改成连续墙体、边缘、沙袋与模块化结构；严格对齐逻辑阻挡，标明装饰/挡路/挡弹，漂亮栏杆不能表现成安全掩体却不挡弹。

用具有不同身形、武器姿态和背负物的三名角色替换胶囊；普通敌人和侧翼敌人先做可区分轮廓。优先待机、走、瞄准、射击、命中、倒地、搜索七组动作，蹲姿与转身接续补齐。动作与固定 tick 事件同步，脚底接地、坡道不漂浮，射击方向与射界一致。

采用共享材质/图集和分档模型；环境细节以墙角、地面材质差、少量管线与物件讲清场景，限制小碎物。前景建筑遮住单位时局部淡化/轮廓提示，但不改变真实 LOS。阴影、接地和枪口闪光优先；不在性能门前引入体积雾、复杂雨、全屏景深或密集动态光。

协作者素材继续按固定提交、许可证、依赖、比例/原点、碰撞语义、面数/材质/纹理预算逐项接入，保留归属；不整包覆盖 PR15。本轮未刷新协作者远端提交，不宣称其最新资产已核对。开工前核对新增素材和最新 PR 状态，再决定复用。真正的交付是手机实际截图与稳定运行，不用概念图代替。

## 7. 玩法与游戏性：提高每个决定的价值

准备期只服务三个问题：“谁守哪里、看向哪里、什么时候发动”。一份清楚的开战摘要显示三人弹药/朝向、已知入口是否有人覆盖与手动/自动许可状态；给可操作提醒，不承诺全覆盖必胜。

保留高点交叉火力与地面爆破两案，检查邻近合理站位容错、错误朝向和无雷反例。高点应提供视线优势并暴露侧翼取舍，不能做唯一正确按钮。移动＋搜索合并上下文链减少重复确认，准备完成不增加强制等待。

失败结算给一个可核验关键事件及定位按钮，例如“侧翼目标于 t=… 越过出口”；建议独立标为建议，允许直接返回本次准备状态。上一方案幽灵和失败点按需显示，帮助有依据地修改。

加少量无数值成长的可选挑战：不用手雷完成、无队员损失、减少弹药消耗。挑战不影响主线解锁，不迫使玩家同时完成，也不先加入大套星级/经济系统。先验证挑战不会破坏两案平衡，再决定是否纳入本阶段。

增加搜索完成、无法射击、齐射、侧翼出现、空弹、结算的短声/轻触觉反馈；重要信息同时可见。静音和减弱闪烁可用。声音和触觉质量需要真人确认。

暂不加入实时战斗微操、完整潜入警报网、可破坏场景、新兵种/武器数量堆叠、局外养成、联网、第七关。

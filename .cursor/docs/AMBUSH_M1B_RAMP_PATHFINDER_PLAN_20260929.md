# M1-B 坡道寻路执行计划

更新日期：2026-09-29。仅用于 Ambush Loop 游戏项目。

## 状态

本计划把《M1 院子高点 ADR》的“坡道寻路”拆成一个可验证的实现切片。它是基于 ADR 的本地执行计划，不是外部 GPT 规划或批准。

- M1-A 高度数据契约：Draft PR #4；定向门已通过，完整隔离冒烟已通过；未合并。
- 本切片：实现中；平地兼容门、M1-A 数据门、R45 门已通过；本切片完整隔离冒烟仍在运行，不能提前记为通过。
- 外部 GPT 规划/评审：待完成。项目对话控制暂时不可用；未发送或伪造评审结果。
- M0 真机复验：按用户要求暂缓。

## 目标

让 A* 寻路在同高相邻格之间维持原有行为，并且只通过关卡显式登记的坡道跨越高差。当前不新增可玩高台、场景视觉或战斗收益。

## 范围

- `RaidPathfinder._neighbors()` 使用 `AmbushGrid.can_traverse_height()` 判断每条候选边。
- 新增隔离门覆盖：平地旧路径、未连坡道时拒绝跨层、坡道连接后可达、坡道移除后不可达，以及路径每条边合法。
- 更新 PowerShell 与 shell 隔离测试入口白名单。
- 不改敌人伤害、命中、射程、警戒、二维 LOS、弹药和关卡布局。

## 验收标准

1. 默认全平地 yard 的短路径仍是五个格点，起终点不变。
2. 相邻地面格与高台格之间没有坡道时，路径为空。
3. 添加显式坡道后，寻路进入高台且返回路径中的每一条边均通过高度可达性检查。
4. 删除坡道后，跨层路径再次为空。
5. M1-A 数据门、R45 独立门与完整隔离冒烟通过；每次测试确认真实存档哈希不变。

## 已知限制与后续

M1-B 只让路径图理解坡道元数据；它没有把坡道放入任一正式关卡，也没有把部署、点击移动或队员物理移动接到高台。故“实际走上高点”的玩法验收仍未完成。下一片需要先明确移动/部署接口，再灰盒一段台面与坡道；之后单独验证垂直遮挡与近身盲区。

浏览器控制器尚不能读取原项目对话时，继续按现有 ADR 实施有限且可逆的代码切片，并在 GitHub 标记外部评审待办；不能把本地分析写成 GPT 已审查。控制器恢复后，应先让 GPT 读取同一项目工作区的规划、差异和测试记录，再依据其独立反馈调整。

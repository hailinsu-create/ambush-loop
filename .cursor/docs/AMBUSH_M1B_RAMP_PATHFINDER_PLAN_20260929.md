## 目标

让 A* 寻路在同高相邻格之间维持原有行为，并且只通过关卡显式登记的坡道跨越高差。当前不新增可玩高台、场景视觉或战斗收益。

## 范围

- `RaidPathfinder._neighbors()` 使用 `AmbushGrid.can_traverse_height()` 判断每条候选边。
- 新增隔离门覆盖：平地旧路径、未连坡道时拒绝跨层、坡道连接后可达、坡道移除后不可达，以及路径每条边合法。
- 更新 PowerShell 与 shell 隔离测试入口白名单。
- 不改敌人伤害、命中、射程、警戒、二维 LOS、弹药和关卡布局。

## 验收标准

1. 默认全平地 yard 的短路径仍是五个格点，起终点不变；六张旧地图的地面邻居图与旧规则一致。
2. 相邻地面格与高台格之间没有坡道时，路径为空；添加显式坡道后双向可达，路径每条边均合法。
3. 验证可选择绕行的备选路线、避让和软代价路径、阻挡端点、删除坡道后断路。
4. M1-A 数据门、R45 独立门与完整隔离冒烟通过；门禁确认真实玩家数据未变化。
5. PR #5 保持 Draft，直到 B2 的玩法接入和设备验收条件另行完成。

## 已知限制与后续

M1-B1 只让路径图理解坡道元数据；它没有把坡道放入任一正式关卡，也没有把部署、点击移动或队员物理移动接到高台。故“实际走上高点”的玩法验收仍未完成。B2 先明确移动、部署、占位和最近开放格接口，再灰盒一段台面与坡道；测试低地→坡道→高台→坡道→低地的完整往返，并核验 `nearest_open()` / `nearest_open_except()` 不会选到高度拓扑上不可达的位置。之后单独验证垂直遮挡与近身盲区。

浏览器控制器仍无法绑定现有 ChatGPT 标签页；本轮通过 Codex 的项目对话集成在同一 Ambush Loop 对话完成了外部 GPT 评审，因而可如实记录上面的反馈。后续规划与每次重要设计调整仍要写入 `.cursor/docs/`、索引并提交到游戏 GitHub。真机复验需在 ADB 稳定识别 `device` 后进行；安装使用保留数据的更新方式，若仍掉线则停止并记录，不卸载或清档。

用户要求审计项目，重点寻找代码优化机会，在新的 `lning` 分支目录通过 PR 交付，并提供实际运行截图。代码分支与工作目录为 `lning`；审计文档使用独立的 `lning-audit` 分支。游戏基线仍为 v0.6.28 / Android code 77。

范围：GDScript 主循环、寻路、存档访问、回放和测试入口。此次不是完整安全审计；不增加玩法、高度系统、新关卡或联网，不修改数值、邻居访问顺序和同代价路径的选择规则。

## 本轮执行切片

1. 在未修改的基线算法上，按种子 `20261002` 建立 504 个确定性查询：六关加泵站关门变体，各 72 个，分普通移动、硬避让、软代价、混合四组。
2. 将 `gscore` / `fscore` 从向量键字典替换为按格子 ID 索引的 `PackedInt32Array`；open 保持首次入队的稳定线性顺序。利用未到达哨兵判断首次插入，删除 `open.find`。保留邻居顺序、禁行、终点修正、扩展上限和回溯语义。
3. 新增 `pathfinder_test.gd` 并加入 Linux/PowerShell 隔离包装器入口；504 条完整路径指纹与基线一致，311 个有效端点查询另外由引擎 `AStarGrid2D` 独立核对可达性和带权最短代价。显式覆盖越界、同点、无路、阻塞/避让端点修正、同代价选路、绕障与门开关，检查输入未被修改。
4. 同一云机、同版引擎、同一输入先执行正确性查询预热，再分别计时。每组 126 次查询，重复 5 次取中位数；只计搜索，排除场景加载、原生最短路对照和指纹计算。比较在全量冒烟与图形采集启动前完成。
5. 按仓库约定，审计/规划文档与实现分别提交独立 PR，各自基于 `main`。仅核对远端完整 SHA 后才能记为已同步，不自动合并。

### 已测寻路结果

| 查询组 | 基线中位数（μs / 126 次） | 优化后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 普通 | 91,879 | 71,859 | 21.8% |
| 硬避让 | 85,221 | 67,146 | 21.2% |
| 软代价 | 92,598 | 72,458 | 21.7% |
| 混合 | 100,338 | 79,081 | 21.2% |

这组结果来自 Godot 4.7.2、Linux 云机的短时微基准，是这些查询的耗时变化，不代表整帧或手机 FPS 提升。路径指纹为 `0b77fff7d2d836cb1eccb589891c1c5f3a6bf5c63b25ea3a8a369e2d6e3aad45`；优化前后均打印 `PATHFINDER_OK cases=504 oracle=311 seed=20261002` 并退出 0。

曾测试稳定的索引最小堆：路径仍等价，但四组耗时增加约 31%–36%，因此未纳入提交。小地图下 GDScript 堆维护成本抵消了复杂度收益；最终代码保留简单队列。

## 验收门槛与风险

- 确定性输入的路径必须与基线逐格相同；等 f 的稳定顺序是行为契约的一部分。
- 覆盖无路、起终点越界/阻塞、起终点相同、硬避让、软代价、门开关、重复搜索及队列优先级降低。
- 性能数字记录工作负载、引擎、重复次数与测量方法；不把微基准当作手机性能证明。
- 原完整冒烟必须从独立 `user://` 启动，并以退出 0、`SMOKE_OK_RAID_LOOP`、六关胜利及 `SMOKE_SLICE_COMPLETE` 为准。
- 网页 GPT PLAN/REVIEW 当前无可用桥接能力，状态为 **unavailable**；没有外部 approve。手机、Android 导出和签名不属于本轮自动验证。
- Git 分支推送可用；GitHub API 的代理 CONNECT 返回 403，尚未进入账号授权检查。已保存只增加 `api.github.com` 的网络配置草稿，当前运行环境仍为旧策略；没有索取凭据或绕过网络限制。

## 后续建议（尚未实施）

1. **存档可靠性**：统一写入入口，检查错误并反馈；按现有版本与迁移约定设计临时文件、校验、替换和恢复。用磁盘不可写/损坏存档等故障注入验证原档保留，不修改正常玩家档。
2. **单次读取快照**：让 `mission_entries` 内部复用一个 `ConfigFile`，验证解锁顺序、老档推断、完美/循环统计与原行为一致，再测实际 I/O 收益。
3. **表现刷新**：先 profile 射界和 HUD，再按几何/样式的真实依赖拆刷新；反例覆盖移动、转向、门、死亡、弹药和选中变化，避免旧射界残留。
4. **维护性**：以后修改主循环时按职责逐步抽出模块；把纯逻辑验证加入短测试入口，同时保留完整六夜冒烟。回放二分查找列为低优先级，先量化快照规模。
5. **结算布局**：先限制容器可用高度、保证按钮可见，再处理长文本滚动；至少覆盖 1280×720 和实际目标手机安全区。

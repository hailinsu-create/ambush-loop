Specific interpretation/implementation risks:

1. `collector_usec = Time.get_ticks_usec()-now` is callback work through row construction and monitor queries, excluding assignment into row and rows.append allocation/array growth. It is not whole CPU frame time, instrument total overhead, or GPU time. Previous callback tail belongs to next interval. Rename interpretation to sample-construction elapsed usecs or move timing after append and document scope. TIME_PROCESS/TIME_PHYSICS_PROCESS are separate engine monitor seconds; render_setup_ms is CPU render setup milliseconds. Do not sum overlapping quantities or label any GPU duration.
2. Wall intervals between post-draw callbacks include game work, software renderer/driver scheduling, limiter/vsync, assertions/driver waiting and instrumentation. Frozen main.set_process(false) probe is explicit instrumentation control; it underrepresents real gameplay. 20 rows/3seconds cannot robustly characterize p99, full-frame costs, shader warm-up or peaks.
3. `-1` distinguishes enum/method absence only. Known monitors can return zero because backend/build support is missing or values lag. Pipeline enum presence does not establish useful Compatibility shader counters; keep availability/backend/build caveat and zero as unproven. Early unavailable render values may also be zero. Original official basis: https://docs.godotengine.org/en/stable/classes/class_performance.html and https://docs.godotengine.org/en/stable/classes/class_renderingserver.html.
4. First-frame exclusion correctly prevents cross-segment interval attribution. mark() unconditionally resets it: only call on actual boundary, not every sample/tick, or all rows become excluded. It does not remove setup cost bleeding into next frames; explicit fixture/setup/capture/seek windows need settling/exclusion. Store skipped spans and reasons; preserve cold spikes separately instead of discarding all phase starts.
5. `rows` is unbounded; per-frame row arrays, monitor-query loops and long retention grow MEMORY_STATIC and CPU cost. Thus observed memory increase includes the collector, potentially mistaken for presentation leak. At minimum record row count/collector storage estimate and subtract only justified instrument baseline; bounded chunk flush outside measured windows or phase-end save/free improves long-run comparability. Disk CSV save is outside marked measurement but rows remain resident until collector freed.
6. `host.presentation_3d` and all three pools/rig are dereferenced without validity checks. Current fixed yard has them; title/scene replacement/reset or missing pool can error. Driver must update host and pause marks across scene transitions, then bind valid presenter/pools. Null-pool is unsupported/absent, not zero active. Connect once, disconnect/free on completion to avoid duplicate sampling. No mutation demonstrated for frozen original fields, but probe check is a bounded before/after subset, not proof all gameplay paths are unaffected.
7. CSV identity is adequate minimal context but needs manifest/extra fields for producer SHA/raw record hash and consumer PCK/game-tree/fixture hash; current metadata source/run alone is insufficient for old-source reference vs new-consumer separation. Add schema/actor/environment revision and record provenance to metadata/segment receipts. record phase vs UI REPLAY phase distinction is already correctly present.
8. Metadata resolution/scale/FPS/vsync is initial only. If workload changes window/scaling/limiter/settings, either freeze them or append per-segment configuration. policy is live host._is_power_saving(); on historical replay it describes renderer policy, not recorded source policy—label accordingly. Include actual sim/play state, engine pause, and camera schedule in segments; sim.paused alone does not identify main.set_process(false), as probe shows.
9. Active counts/rejections are read per rendered frame, useful peaks at frame resolution. Pool capacities, cache capacity, culled/dropped descriptors and stable mesh/material resource identities absent; add constants/config to metadata and explicit saturation/dropped counters only where available. Rejections are cumulative: report segment deltas and baseline; do not interpret totals as per-frame failures. Unsupported density can leave active0 while failing to render source FX; success/descriptor support coverage stays independent.
10. Memory/static/object/resource monitors are engine allocation/counts, not process RSS/true graphics VRAM (especially llvmpipe). Collect owned-PID RSS/cgroup separately and record concurrent host work. Separate display prevents native collisions but not CPU contention. No unrelated agents/engine jobs during clean timing windows, or explicitly mark contaminated windows.

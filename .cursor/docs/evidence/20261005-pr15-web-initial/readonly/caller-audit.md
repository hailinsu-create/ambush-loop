No engine/browser/attach/profiling/export/assets were operated. Existing diagnostic evidence was not changed. Downloaded exact official source ed1daf0bf001b61586d9930840f2f1394092c079 into this independent directory. Scope is source and recorded observer evidence, not fresh reproduction.

## Confirmed evidence

Existing webgl-binding-diagnostic/report.json records8 invalid binds, one unique anonymous stack: wasm-function17244→50552→36343→36395→67820→19479→1679→60715, target34962/previous34963. Console records paired INVALID_OPERATION bindBuffer and bufferSubData:no buffer. This proves target-class conflict at runtime; function names remain unidentified. It does not prove the named C++ caller.

Official drivers/gles3/storage/mesh_storage.cpp:267–270 allocates index buffer as ELEMENT_ARRAY_BUFFER;584–596 mesh_surface_update_index_region binds that same index buffer to ARRAY_BUFFER and updates it. This is a real source defect matching the observed error shape. Other update_vertex/attribute/skin functions539–581 use their intended non-index fields. mesh_get_surface648/655 and Utilities.buffer_get_data123–147 preserve the supplied ELEMENT target; official platform/web/js/libs/library_godot_webgl2.js40–44 passes target unchanged to getBufferSubData. These inspected readback paths do not establish the error.

Crucial built-in caller: official scene/2d/polygon_2d.cpp119–122/361–434. Polygon2D's redraw prepares an indexed surface. When topology/UV/color-layout/bone-presence counts do not require clear(365–369),419–425 updates vertex, optional attributes AND index region424. Thus absence of a GDScript mesh_surface_update_index_region invocation does not exclude this defect. RenderingServerDefault forwarding is servers/rendering/rendering_server_default.h403. Public registration is rendering_server.cpp2387. Source search of extracted scene/rendering/GLES files found Polygon2D as the concrete internal update caller; not PrimitiveMesh, ImmediateMesh, Label3D or Sprite3D. This is a source-reachable chain, not symbolization of the observed WASM stack.

## Minimal workaround candidates and traps

1. If root proves offending work is exclusively legacy presentation under the existing active3D gate, avoid constructing/redrawing those legacy visual markers while preserving replay source, simulation actors, UI/source selection and3D presentation. Gate the presentation routine, not World.visible or whole-subtree process participation: those can alter simulation semantics the current RS hide intentionally preserves. Source audits plus original backend/event/record invariance and same history/camera acceptance are necessary.
2. If a genuinely displayed Polygon2D is identified, a Web-only replacement/rebuild of that visual node/mesh or equivalent indexed-free CanvasItem drawing is an application-level candidate. Preserve all transforms/material/color/UV/ordering/input and references. Do not touch authored GLBs/manifests or patch bindBuffer in JavaScript; do not suppress GL errors.
3. polygon=[] then restore is NOT proven rebuild: set_polygon440–443 only stores points and queues deferred redraw; updates can coalesce. Even an actual empty DRAW returns at119–122 without updating last_len or clearing mesh. Therefore clearing/restoring points can re-enter the same no-clear branch. A truly different valid topology must pass a redraw to alter internal state, or the node must be recreated; the former causes intermediate visual workload and is not an automatically safe workaround. Restrict any experiment to root's controlled slice.

Required root-owned proof: same bad bind stack disappears for the specifically identified node path without observer interception; fresh Title/live and original history seek/1x/2x/pause/eventfocus keep source/event/statistics/pose/asset identities; all visible required geometry remains; console no bindBuffer/bufferSubData errors. Current released candidate retains recorded GL errors, and this report does not change its acceptance status.

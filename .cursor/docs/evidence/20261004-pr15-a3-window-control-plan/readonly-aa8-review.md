## Paired collector-overhead control

No unattached/attached implementation appears among current a3 scripts; a3_collector_probe_test.gd is collector-on only. Measured collector_usec quantifies its callback construction, not effect on rendered cadence or total process RSS.

Design two distinct pairs, each labelled:

A. callback-only overhead: allocate/verify identical collector in both conditions, keep payload resident, run fixed lightweight cadence sampler in both. Attached condition connects _sample; unattached condition stop()/disconnects _sample after setup, retaining allocation. Pin production frame/source/camera/state/policy/window/scale/maxFPS/vsync/audio/renderer and warm-cache conditions. This pair estimates incremental callback/storage writes. It cannot estimate allocation/proof/hook startup overhead because both pay it.

B. total instrumentation overhead: minimal cadence sampler present in both; baseline never instantiates full collector, instrumented condition does. Seal proof outside measured windows via external trusted receipt, and report memory/static/RSS difference separately. Identical lightweight sampler's own overhead is shared. Full collector preload may still load script resources in baseline—state this scope; no instrumentation buffer allocated there.

Use matched warm paths with AB/BA or ABBA order, repeated per condition, same single-host single-engine serial window. Compare median/p95/p99 cadence distribution with durations/sample counts and spread; avoid one3sec A then B as conclusive because driver cache, temperature/sharedhost/load order drift remain. The source-captured scene/state digest and rendering draw/primitives should match workload; attached/unattached runtime attempts may differ IDs, so compare semantic state/event/record hashes, not literal attempt ID. Keep random seed and source derived state fixed. Preserve raw baseline timestamps plus per-condition configuration receipts and actual exits; no screenshot/assert/print during timing.

Frozen-yard matched pair verifies stationary instrumentation cost only. For formal actual dynamic source/replay use same pinned original record playback/source schedule and camera schedule; compare equal recorded-clock windows/phase and policy, not just equal wall duration, because collector load can change wall-clock rate/fractional playback progression. FULL record end-to-end and identical terminal/events/HP/ammo/record invariants are additional gates. Use timestamp sampler on unattached run; without it there is no comparable raw render cadence.

Do not subtract callback_usec from frame intervals to invent corrected FPS: callback work can affect scheduling, caches and software renderer overlap nonlinearly. A capped30FPS/vsync pair can conceal incremental work below frame cap; record both configured cap and work counters, optionally separate explicitly uncapped instrumentation controls, without treating controls as Android gameplay. Collector memory baseline at default32768x59x8=15,466,496 numeric bytes plus symbols/metadata matters; reuse same capacity for callback-only pair.
